# Проверки и выпуск

Фронтенд и бэкенд имеют отдельные репозитории, образы и CI. Общий Compose запускает их проверенные версии вместе; исходники не копируются.

## Бэкенд

Работа выполняется в ветке от dev. Перед объединением проверяются Ruff, форматирование, строгий Pyright, unit/integration с покрытием не ниже 90%, системный контракт, Swagger Try it out/Execute, почта, оплата, перезапуск и миграция существующих данных.

Для dev/master CI собирает отдельные кандидаты API и почты на native AMD64 и ARM64. Образы маркируются SHA коммита и проверяются по неизменяемому digest. Trivy блокирует исправимые HIGH/CRITICAL уязвимости обоих кандидатов.

После успешных обязательных проверок master публикует:
- `andymentor/swagger-petstore:sha-<commit>` и `latest`;
- `andymentor/swagger-petstore-mail:sha-<commit>` и `latest`.

Публикация объединяет только проверенные digest без новой сборки и проверяет, что коммит всё ещё является текущим master. Изменения документации не запускают ненужный выпуск runtime; неизвестный путь включает полные проверки.

## Фронтенд

Собственный CI проверяет TypeScript, unit-тесты, моковые браузерные сценарии, настоящий API/SMTP и изображения учебного каталога. API и почта закрепляются на проверенных тегах в тестовом Compose. Изолированные тестовые тома не совпадают с рабочими.

Кандидат `andymentor/lapki-frontend` собирается в API-режиме, проверяется браузером и сканером. После успешных проверок master продвигает его digest в `sha-<commit>` и `latest` без пересборки.

Docker Hub token хранится только в зашифрованных GitHub Actions Secrets. В код, диагностические логи и Compose он не включается.

## Совместимость и откат

Для воспроизводимого стенда фиксируются теги API, фронта и почты. Обновление одной стороны должно проходить UI/API-сценарии с конкретной совместимой версией второй.

База, медиаданные и почта сохраняются в отдельных томах. Первые 12 SQL-миграций и их checksum неизменны. Старый общий контейнер необходимо остановить до подключения его тома к отдельному PostgreSQL.

До обновления сохраняется резервная копия БД и прежние версии образов. Для отката возвращаются прежние версии и настройки; одновременно два PostgreSQL на одном томе не запускаются. Рабочий `.env` и приватные задания не публикуются.
